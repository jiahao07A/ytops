# ADR 0002：观看口径双采（播放口径 + 互动口径）

- 状态：已接受
- 日期：2026-08-30
- 影响范围：`src/lib/analytics.ts`（核心指标白名单）、`src/lib/breakdowns.ts`、`src/lib/config.ts`、后续规格与 skills 文档

## 背景

2026-08-24 起官方将全格式观看计数统一为"开播即计"（播放口径），且历史数据不重述；官方同时定义互动口径（观看越过第一帧）为跨改版前后对比的指定口径，查询式 Analytics API 自 2025-04-30 起支持该指标（任意历史范围、可按单视频过滤）。仓库此前仅同步单一 views 口径。

## 决策

1. 核心同步与高维细分**同时保存两种口径**：播放口径（views）与互动口径（engagedViews）。播放口径保持与公开计数器及既有历史序列的连续性；互动口径作为跨改版对比与收入类派生指标的一致基准。
2. **历史不重述**：改版生效日前日期的播放口径序列按当时口径保留，不做任何改算或回写。
3. 派生指标（RPM 等）一律**读取时计算**，仓库只保存原始量，不落计算值。
4. 派生指标默认使用**互动口径分母**，与官方"收入锚定互动观看"的表述一致。

## 备选方案

- **单播放口径采集**：跨 2026-08-24 边界的序列不可比，官方指定的对比口径被放弃。
- **单互动口径采集**：失去与公开计数器、既有同步数据的连续性。

## 风险与后果

- 两个"观看数"并存，读取端易混淆；以 CONTEXT.md"观看口径"术语与文档约束表述。
- 官方未说明互动口径对 Shorts 2025-03-31 之前是否有回填，极早期 Shorts 序列可能两种口径缺一。
- engagedViews 与 views 同查询获取，仅增加响应体积，不增加请求数。
