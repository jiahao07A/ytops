# YouTube 运营数据工具真实可用性与持续同步闭环

Type: spec
Status: open
Labels: ready-for-agent

## Problem Statement

频道运营者已经可以从当前 CLI 看到公开内容检索、频道接入、首条链路数据基线、核心与高维 Analytics、异步 Reporting、只读评论和覆盖矩阵等功能，但这些能力目前主要由离线 provider 和合同测试证明。真实 `yt-dlp`、真实 Google OAuth、Windows 受保护凭据、令牌续期和官方 API 最小读取尚未形成完整验收证据，因此“代码存在”和“离线测试通过”仍不能等同于“日常可用”。

现有配置已经表达同步频率、并发、配额预算、首次回填窗口和原始证据保留期，但运行层没有真正执行所有到期同步任务的调度闭环。频道运营者仍需人工重复运行命令，Reporting 的等待状态也不会自动推进，访问令牌过期后缺少已证实的自动续期路径。

数据正确性仍存在若干会影响事实查询可信度的风险：公开内容检索可能把执行权限问题误报为未安装；同步任务的终止性失败可能被调用方误判为成功；Analytics 的合法空结果、日期窗口隔离和高维分页需要补全；Reporting 的创建合同、报告分页、新日报发现、报告类型隔离和 CSV 解析需要与官方协议闭环；评论回复未完整获取时必须保持部分覆盖状态。

频道运营者需要的是一个可持续运行、可恢复、可核验的只读运营数据工具，而不是一个只能证明离线代码路径存在、却无法确认真实环境和长期同步是否成立的实现。

## Solution

在保留本机、单用户、CLI-first 和只读运营操作边界的前提下，为现有工具补齐三个闭环：

1. **真实可用闭环**：让公开内容检索、频道接入初始化、Windows 受保护凭据、OAuth 自动续期和官方 API 最小读取均具有脱敏、可复查的真实环境验收证据。
2. **持续同步闭环**：以频道接入、数据源和同步范围为隔离单位，提供可重复执行的到期任务运行周期，并由用户显式注册的 Windows 系统调度任务定期触发；同步在中断、重启、配额耗尽和异步等待后能够继续推进。
3. **数据可信闭环**：完整处理官方分页和合法空结果，隔离不同窗口、报告类型及分析配置档案，统一任务状态与退出语义，并让事实查询持续提供数据截至时间、覆盖状态、最近刷新结果和脱敏原始证据引用。

公开内容检索继续使用成熟的 `yt-dlp`；官方频道数据继续通过窄 provider 边界接入，但由官方 Google API Node 客户端负责 OAuth、Data API、Analytics 和 Reporting 的请求合同。CSV、并发限制和跨进程锁分别使用成熟依赖或仓库已有依赖，不再手写通用解析、调度或互斥协议。

## User Stories

1. As a 频道运营者, I want 健康检查区分未安装、无执行权限、程序损坏和外部命令失败, so that 我可以按明确建议修复公开内容检索环境
2. As a 频道运营者, I want 关键词检索在真实环境中返回稳定 JSON, so that 我可以直接发现公开内容
3. As a 频道运营者, I want 单视频详情查询返回稳定 JSON, so that 我可以核对候选内容的基础元数据
4. As a 频道运营者, I want 字幕可用性查询返回稳定 JSON, so that 我可以判断候选内容是否具有可用字幕
5. As a 调用方, I want CLI 和内部检索入口使用同一套搜索词与数量边界, so that 绕过 CLI 不会产生非法检索请求
6. As a 调用方, I want 畸形或不完整的外部 JSON 被明确报告为响应错误, so that 异常结果不会被静默解释为空列表
7. As a 频道运营者, I want 按 OAuth 配置指导建立频道接入, so that 我可以使用官方授权读取自己的频道数据
8. As a 频道运营者, I want 授权后看到所有可访问频道并明确选择目标频道, so that 一个 Google 身份下的多个频道不会被错误接入
9. As a 频道运营者, I want 访问令牌过期后自动使用受保护的刷新令牌续期, so that 我不需要频繁重新授权
10. As a 频道运营者, I want 进程重启后仍能使用受保护凭据完成续期, so that 日常同步不会依赖常驻进程内存
11. As a 频道运营者, I want 撤销授权、缺少刷新令牌、权限不足和网络失败成为不同状态, so that 我知道应重新授权、重试还是缩小同步范围
12. As a 频道运营者, I want 收入数据只在我显式申请货币 Analytics 权限后查询, so that 高权限 scope 不会被默认申请
13. As a 安全负责人, I want 令牌、客户端秘密和 Authorization 头永不进入 JSON、日志、状态或原始证据, so that 受保护凭据不会因排错和同步泄露
14. As a 频道运营者, I want 频道接入初始化后完成可恢复的首次回填窗口, so that 运营数据仓库具有明确的数据起点
15. As a 频道运营者, I want 系统按已配置频率运行所有到期同步任务, so that 首次回填后数据能够持续更新
16. As a 频道运营者, I want 调度任务的安装、查看和停用都由我显式执行, so that 本机不会出现不可见的后台行为
17. As a 频道运营者, I want 漏跑的同步在下一次调度时得到补偿, so that 重启或关机不会永久留下数据缺口
18. As a 频道运营者, I want 网络中断、配额耗尽或进程终止后从检查点继续, so that 已确认的数据不会被重复全量下载
19. As a 频道运营者, I want 不同频道接入和同步范围彼此隔离, so that 一个任务的状态不会污染另一个任务
20. As a 频道运营者, I want 同一同步任务最多只有一个执行者, so that 并发命令不会互相覆盖运营数据仓库
21. As a 频道运营者, I want 不同同步任务可以在并发上限内运行, so that 多个数据源可以有效利用允许的资源
22. As a 频道运营者, I want 配额预算在任务开始和翻页前得到执行, so that 单次同步不会静默超出频道配置
23. As a 频道运营者, I want 手动源站刷新继续支持最后可用数据回退, so that 暂时的源站失败不会阻断低风险分析
24. As a 频道运营者, I want 强制最新查询只在本次源站刷新成功后返回, so that 高风险流程不会误用陈旧数据
25. As a 调用方, I want Analytics 合法无数据被表达为空事实集, so that 没有数据不会被误判为外部响应损坏
26. As a 调用方, I want 缺失指标保持缺失而不是被转换为零, so that 资格限制和真实零值不会混淆
27. As a 调用方, I want 核心 Analytics 和高维细分数据完整处理分页, so that 大结果集不会被静默截断
28. As a 调用方, I want 不同日期窗口、频道、维度组合和分析配置档案具有独立状态, so that 旧窗口行不会污染新事实查询
29. As a 频道运营者, I want Reporting 按官方合同创建报告任务, so that 真实 API 不会因请求形状错误而拒绝
30. As a 频道运营者, I want Reporting 完整遍历报告列表并选择所有尚未导入的新报告, so that 新日报不会因分页或顺序被遗漏
31. As a 频道运营者, I want 已导入的 Reporting 任务继续发现后续日报, so that 持续同步不会在第一次导入后停止
32. As a 频道运营者, I want 不同 Reporting 报告类型使用独立 job、检查点和数据, so that 一种报告不会被导入另一种报告的范围
33. As a 频道运营者, I want Reporting 的等待、重试、远端失败和就绪状态被明确区分, so that 调度可以自动决定下一步
34. As a 调用方, I want 引号、逗号、嵌入换行、空值和重复行都能被可靠解析, so that 官方 CSV 可以幂等导入
35. As a 频道运营者, I want 评论线程和回复按官方分页能力读取, so that 可授权取得的回复不会被遗漏
36. As a 频道运营者, I want 无法完整取得回复时覆盖状态明确为部分支持, so that 部分评论不会被误认作全部评论
37. As a 调用方, I want 同步任务统一显示排队、运行、等待、重试、部分完成、失败和完成, so that 自动化可以依据结构化状态做决策
38. As a 调用方, I want 终止性失败返回失败 JSON 和非零退出码, so that 任务失败不会被顶层成功标记掩盖
39. As a 调用方, I want 异步等待返回可重试状态和下一次重试时间, so that 等待不会被误判为失败或完成
40. As a 频道运营者, I want 每项事实查询显示数据截至时间、覆盖状态和最近刷新结果, so that 我可以判断数据是否足够新且可用
41. As a 频道运营者, I want 从事实查询定位脱敏原始证据和请求条件, so that 我可以复查规范化结果
42. As a 频道运营者, I want 原始证据保留期实际生效而规范化数据不被自动删除, so that 本机容量策略不会破坏长期事实数据
43. As a 维护者, I want 现有配置和运营数据仓库通过幂等迁移继续可用, so that 补全工作不会要求用户丢弃已有数据
44. As a 维护者, I want 使用测试频道完成两轮真实增量同步、一次令牌续期和一次重启恢复, so that 持续运行能力得到真实证据而非仅由 mock 证明
45. As a 维护者, I want 真实验收只保存脱敏命令、状态和证据摘要, so that 凭据、频道内容和原始报告不会进入 Git

## Implementation Decisions

- 本规格作为独立的生产可用性补全工作维护；既有已解决规格和票据保留为历史证据，不回写为未完成。
- 保持本机、单用户、CLI-first、只读运营操作边界。公开内容检索与 YouTube Studio 运营数据保持独立适配层，共享稳定的 JSON、错误和进程执行合同。
- 公开内容检索继续委托 `yt-dlp`。搜索词、数量范围和响应结构在公共边界统一验证；合法空结果与畸形响应必须区分。
- 健康检查和外部进程错误分类至少区分：可执行文件不存在、无执行权限、程序损坏或无法启动、外部进程非零退出、输出无法解析。每类错误提供可操作建议。
- 官方 OAuth、YouTube Data API、YouTube Analytics API 和 YouTube Reporting API 由官方 Google API Node 客户端承载；业务层继续依赖窄 provider 接口，以保留离线替身和未来迁移边界。
- OAuth provider 增加刷新令牌 grant。新响应包含轮换后的刷新令牌时原子替换；未返回刷新令牌时保留旧值。受保护凭据更新采用单飞控制，避免同一频道并发刷新。
- 数据能力决定最小 scope。基础数据、评论、普通 Analytics 和货币 Analytics 分开申请；收入数据在缺少货币 scope 时返回明确的资格限制，不尝试隐式扩权。
- 同步任务身份由频道接入、数据源、同步范围以及适用的分析配置档案、报告类型或日期窗口共同确定。不同身份不得共享 job、页令牌、检查点或规范化结果文件。
- 任务状态统一为 `queued`、`running`、`waiting`、`retrying`、`partial`、`failed` 和 `completed`。状态包含最近尝试时间、是否可重试、下一次重试时间、数据截至时间和脱敏错误分类。
- 终止性失败返回 `ok: false` 和非零退出码。`waiting`、`retrying`、`partial` 等非终止状态可以返回 `ok: true`，但必须携带结构化任务状态；调用方不得只依据顶层 `ok` 判断同步完成。
- 调度核心公开一个可重复执行的“运行所有到期任务”周期。CLI 提供 `ops channel scheduler run`、`install`、`status` 和 `disable` 四个稳定 JSON 命令。
- `scheduler run` 是一次性、可重入的执行周期，不启动自制常驻守护进程。Windows 定期触发通过系统 Task Scheduler 完成；注册、变更和停用必须由用户显式执行，并展示目标命令、频率和本机影响。
- 使用伪时钟计算任务是否到期、漏跑补偿、退避和 Reporting 下一次轮询时间。运行时使用持久化时间戳，不以进程存活时间作为事实来源。
- 使用现有成熟文件锁依赖为同一任务提供跨进程互斥；使用成熟并发限制依赖执行不同任务。崩溃后锁可恢复，原子写入继续用于状态、数据和受保护凭据更新。
- Inventory 的同步范围依赖被明确校验。缺少发现视频所需的频道或上传播放列表信息时，不得以空完成掩盖无效范围；CLI 默认范围不得意外重置可恢复检查点。
- 核心 Analytics 从官方要求的 1-based 起始索引开始并消费所有页。响应缺少或包含空 `rows` 时视为成功的空事实集；缺失值保持缺失。
- Analytics 数据按完整查询身份隔离。日期窗口或分析配置档案改变时不合并旧身份的行；需要迁移时保留历史数据并建立新身份，而不是破坏性清空。
- Reporting 创建请求包含官方要求的名称和报告类型。报告列表完整消费分页，按生成时间和已导入记录选择所有新报告；已导入状态不阻止发现后续日报。
- 每种 Reporting 报告类型具有独立 job 和检查点。远端失败成为终止或可重试状态；没有可下载报告时进入带下一次轮询时间的 `waiting`。
- Reporting CSV 使用成熟解析器，支持标准引号、分隔符、嵌入换行和空值。导入以稳定行身份幂等去重，原始文件与规范化事实分开保存。
- 评论同步在权限允许时通过官方回复列表分页补齐线程回复；无法完整取得时保留 `partial`，并说明未覆盖原因。
- 普通事实查询继续允许返回带过期标记的最后可用数据；强制最新查询只有源站刷新成功才返回事实。合法空结果只有在覆盖和刷新成功时才能成为新的最后可用数据。
- 原始证据保留期由到期任务周期执行，但只清理明确频道接入和数据源范围内的原始证据。规范化数据不自动删除。
- 兼容现有配置、运营数据仓库和 JSON 消费方。任何状态或目录迁移必须幂等、可恢复、可重复执行，并在失败时保留旧数据。

## Testing Decisions

- 好测试只验证用户可见行为和稳定公共合同，不断言内部函数调用顺序、私有函数或临时目录布局。
- 自动化测试的最高接缝是构建后的 `ytops --json` CLI。每个端到端合同测试断言退出码、标准输出仅包含一个可解析 JSON、标准错误、`ok/data/error` 结构、任务状态以及再次读取后的持久化结果。
- CLI 测试使用临时运营数据仓库、伪时钟、可控 `yt-dlp` 可执行替身和伪官方 provider，不访问真实账号或网络。
- Google/YouTube provider 保留必要的窄合同测试，通过可注入传输层验证 HTTP 方法、URL、查询参数、请求体、授权头、分页令牌和错误映射。若官方客户端隐藏传输细节，则断言客户端方法参数和归一化结果，不复制其内部实现。
- 基础搜索测试覆盖关键词、1-50 数量边界、合法空结果、畸形 JSON、缺少字段、异常条目，以及未安装、无执行权限、程序损坏和非零退出的独立错误映射。
- OAuth 测试覆盖授权码交换、过期令牌续期、刷新令牌轮换、保留旧刷新令牌、同一频道单飞刷新、进程重启恢复、`invalid_grant`、撤销、网络失败、权限不足和货币 scope。
- 凭据安全测试扫描 JSON、标准输出、标准错误、任务状态和原始证据，确保令牌、客户端秘密和 Authorization 头均未出现。
- Inventory 测试覆盖频道、上传播放列表和视频的多页链路、批次边界、重复项、变化或删除的资源、网络中断、检查点恢复、无效同步范围、重复执行幂等和并发锁。
- 核心与高维 Analytics 测试覆盖 1-based 分页、后续页、缺少或为空的 `rows`、缺失指标、窗口/频道/维度/档案隔离、配额、权限、最后可用数据回退和强制最新失败。
- Reporting 测试覆盖官方 job 创建参数、报告列表分页、按时间选择新报告、导入后继续发现日报、报告类型隔离、waiting/retry/failed 状态、下一次重试时间和幂等恢复。
- CSV 测试覆盖引号、逗号、嵌入换行、空值、重复行和大文件流式解析，预期值来自独立 fixture，不用生产解析逻辑重新计算。
- 评论和覆盖矩阵测试覆盖多页线程与回复、检查点恢复、重复评论、空频道、权限或配额限制、部分回复状态、数据截至时间和证据引用一致性。
- 调度测试从 CLI 使用伪时钟覆盖首次运行、频率、漏跑补偿、重启恢复、Reporting 轮询、退避和配额预算，不依赖真实等待。
- 并发测试并行启动构建后的真实 CLI 进程，验证同一任务只有一个执行者、不同任务遵守并发上限、OAuth 刷新单飞、崩溃后锁恢复且状态文件不损坏。
- 状态与退出语义测试覆盖所有任务状态。终止性失败必须为 `ok: false` 和非零退出码；等待、重试和部分完成必须包含结构化状态及下一次可重试时间。
- 沿用现有 Vitest、临时目录、伪 provider、伪 fetcher、CLI 子进程和 Windows 条件式 DPAPI 测试模式。所有自动化测试以 `npm run verify` 通过为质量门禁。
- 真实环境验收是独立且不可替代的人工接缝，不进入普通 CI。使用测试频道完成真实 `yt-dlp`、OAuth、显式频道选择、DPAPI、令牌续期、进程重启、两轮增量同步以及 Reporting 从等待到导入。
- 真实环境不强求目标频道不具备资格的数据存在；资格不足时，正确的覆盖状态和错误分类就是验收结果。
- 真实验收只保存脱敏命令、退出码、任务状态、数据截至时间和证据摘要；真实凭据、频道内容、原始 API 响应和报告文件不得进入 Git。

## Out of Scope

- YouTube Studio 网页 UI 的逐项镜像、网页抓取、浏览器 Cookie 绕过以及未被官方接口证实的数据。
- 上传、发布、编辑、删除、隐私或排程修改、回复评论以及其他频道写入。
- 高级公开内容搜索产品能力，包括长期搜索索引、跨查询历史、个性化排序和任意组合筛选。
- 直播数据、实时推送或对 YouTube 官方数据延迟作零延迟保证。
- MCP 适配层、前端界面、内置 AI 因果分析和自动运营建议。
- 自制常驻守护进程、服务器部署、多用户共享、远程凭据托管和跨机器同步。
- 对 content owner 专属报告、收入资格、隐私阈值和官方历史窗口作无条件完整保证。
- 自动删除规范化数据，或把真实凭据、频道内容、原始 API 响应和原始报告提交到仓库。

## Further Notes

- 本规格来源于 [当前仓库主要功能实现审计](../youtube-studio-data/implementation-audit.md)，其结论区分了代码存在、离线自动化证据、真实环境验证和明确非目标。
- 现有 YouTube Studio 数据规格及 01-10 号票据继续代表首轮离线实现历史；本规格只描述其上线前补全和持续运行合同。
- `ready-for-agent` 表示本规格已经具有足够范围、验收边界和技术决策，可以继续拆分为独立 tracer-bullet 票据；不表示这些能力已经实现。
- Windows Task Scheduler 的安装会改变本机外部状态，后续实现和验收都必须在执行前向用户展示将注册的任务并取得明确确认。
