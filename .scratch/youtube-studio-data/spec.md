# YouTube Studio 运营数据本机仓库与 CLI

Status: resolved

> 本文件记录频道数据获取路线与验收合同。当前实现仍以 README、`docs/architecture.md` 和代码为准；01-10 号任务均已完成离线实现，真实账号 OAuth/API 验收仍需人工执行。

## Problem Statement

频道运营者无法以可复查、可配置且安全的方式，将自己 YouTube Studio 中经官方授权可读取的运营数据接入本机数据仓库。当前 CLI 已能完成只读 OAuth 授权、频道发现和显式选择，但仍不能同步数据、说明数据新鲜度，或向外部 AI 提供完整的事实查询接口。

“获得 Studio 的所有数据”不能承诺网页 UI 的逐项镜像。产品需要以官方用户 OAuth 可访问的数据能力和覆盖矩阵作为完整性定义，明确说明资格限制、估算值、异步报告与不可用数据，避免把缺失或延迟数据误报为零值或实时值。

## Solution

提供一个本机单用户的 YouTube Studio 运营数据仓库，以及一组稳定、只读、支持 JSON 输出的 CLI 工具。每个频道接入独立建立；用户完成 OAuth 后必须从可访问频道列表中明确选择一个频道。系统将尝试回填默认最近 365 天、最多可配置 3650 天的首条链路数据基线；实际覆盖范围受 OAuth 权限、频道资格、指标可用窗口和官方延迟影响，并必须在结果中标明部分覆盖或不可用状态。之后按配置每日同步，并允许按需查询高维细分数据。

CLI 只负责同步、状态、事实查询和证据查看。任意 AI 客户端可以调用这些工具并据此分析，但 CLI 不内置模型、不输出未经证实的因果结论。所有结果附带数据截至时间、覆盖状态和来源证据；令牌与客户端秘密仅保存在操作系统受保护凭据存储中。

### 验收标准

- 用户能在不暴露秘密的前提下完成 OAuth 配置指导、授权和明确频道选择。
- 用户能为一个频道建立频道接入并请求可恢复的、默认 365 天且最大 3650 天的首次回填；若官方能力不足，结果明确返回实际覆盖范围及部分覆盖、不可用或权限不足状态。
- 用户能通过 CLI/JSON 查看同步状态、覆盖状态、数据截至时间和最后可用数据。
- 用户能查询首条链路数据基线，并能按配置或临时参数请求高维细分数据。
- 刷新失败时默认返回显式标记为过期的最后可用数据；强制最新查询则失败。
- CLI 不执行频道写入操作，不包含令牌或客户端秘密，也不把受限、估算或延迟数据伪装成正常数值。

## User Stories

1. 作为频道运营者，我希望获得 OAuth 配置的逐步指引，以便安全地准备 Google Cloud 和本机环境。
2. 作为频道运营者，我希望通过官方用户 OAuth 授权，以便只授予读取本人频道数据所需的最小权限。
3. 作为频道运营者，我希望在授权后查看可访问频道列表并明确选择一个频道，以便不会误接入错误频道。
4. 作为频道运营者，我希望每个频道都有独立的频道接入和同步状态，以便分别管理多个频道。
5. 作为频道运营者，我希望首次建立频道接入时默认回填最近 365 天，并可将窗口配置到最多 3650 天，同时看到实际覆盖范围，以便知道哪些历史数据可分析。
6. 作为频道运营者，我希望同步频道、视频和上传播放列表元数据，以便识别可分析的内容范围。
7. 作为频道运营者，我希望同步频道和视频级表现与互动数据，以便比较内容的真实表现。
8. 作为频道运营者，我希望将流量来源、设备、地域、受众和收入等高维细分数据按需获取，以便在不浪费配额的情况下深入分析。
9. 作为频道运营者，我希望配置默认每日同步、频率、并发和配额预算，以便适配不同频道的运营节奏。
10. 作为频道运营者，我希望中断的同步从检查点恢复，以便网络或配额问题不会导致重复下载全部数据。
11. 作为频道运营者，我希望临时通过 CLI 参数改变同步范围或分析口径，以便快速回答一次性问题。
12. 作为频道运营者，我希望把常用的临时口径保存为分析配置档案，以便稳定复用。
13. 作为频道运营者，我希望运行配置初始化、校验和解释命令，以便大量配置项仍然易于理解和排错。
14. 作为频道运营者，我希望配置辅助 skill 能读取现状、提议差异、征得确认后写入并校验配置，以便 AI 可以安全协助初始化和修复配置。
15. 作为频道运营者，我希望查询结果显示数据截至时间、来源和覆盖状态，以便判断结论是否足够新且可用。
16. 作为频道运营者，我希望源站刷新失败时仍能获得最后可用数据及其过期标记，以便不中断低风险分析。
17. 作为调用方，我希望使用强制最新查询，以便在需要最新官方结果的自动化流程中拒绝陈旧数据。
18. 作为调用方，我希望获得稳定的 JSON 事实输出，以便任意 AI 客户端或脚本能可靠调用而不依赖人类可读文本解析。
19. 作为调用方，我希望查看原始证据和请求条件，以便复查规范化数据和 AI 使用的事实基础。
20. 作为频道运营者，我希望收入估算、受众隐私阈值和资格限制被明确标记，以便不会把不可用数据误判为零。
21. 作为频道运营者，我希望规范化数据默认不自动删除，而原始证据可按频道配置保留期，以便兼顾长期分析和本机容量。
22. 作为安全负责人，我希望令牌、客户端秘密和其他受保护凭据永不出现在配置、日志、JSON 输出或 Git 中，以便降低凭据泄露风险。
23. 作为未来的维护者，我希望本机仓库与官方 API 适配层有清晰边界，以便后续迁移到服务器时不改变 CLI 事实合同。
24. 作为频道运营者，我希望看到覆盖矩阵中已支持、部分支持、资格限制、估算或会调整、异步处理中和不可用的状态，以便准确理解“完整”的边界。

## Target Design Decisions

以下决策同时作为当前只读实现的边界；真实 API 的资格、配额和历史窗口仍以运行时返回为准。

- 使用官方用户 OAuth 2.0 访问私有频道数据；不使用 service account、浏览器 Cookie 或网页自动化。授权后枚举可访问频道，用户必须显式选择目标频道。
- 建立以频道为单位的频道接入、同步任务、同步范围和检查点模型。一个 Google 身份可管理多个独立频道接入，但不能通过默认值隐式选择频道。
- 首条链路数据基线包括频道、视频、上传播放列表元数据，以及频道和视频级表现与互动数据。直播不在本期范围；Reporting、评论和其他数据源在首条链路稳定后按覆盖矩阵扩展。
- Analytics 查询采用经校验的指标、维度和兼容组合目录。高维细分数据按分析配置档案或临时参数请求并缓存，不预下载所有组合。
- 数据仓库同时保存用于查询的规范化数据和可复查的原始证据。原始证据保存请求条件、来源、获取时间、页或报告进度与校验信息，但不保存凭据。
- 规范化数据不自动删除；原始证据默认保留 365 天，支持按频道覆盖和显式清理。清理行为必须只针对明确选定的频道与数据范围。
- 同步默认每日运行。配置可控制频率、并发、配额预算、范围和保留期；同步范围可由 CLI 临时覆盖或持久化为配置。
- 每个同步范围保留可恢复检查点。配额不足、网络中断、异步报告尚未就绪和权限不足都必须成为可观察状态，而非静默成功。
- 事实查询默认读取最后可用数据；显式刷新会先尝试源站刷新。刷新失败时返回带过期状态的最后可用数据，强制最新查询不允许该回退。
- CLI 提供同步、状态、事实查询、证据查看和配置管理的稳定 JSON 合同。它不生成因果归因或自动结论；AI 客户端在其上层负责分析。
- 配置分为全局运行配置、单频道同步配置和分析配置档案。配置辅助 skill 放在仓库内，支持初始化、校验、解释和修复配置，并在任何写入前展示差异并请求确认。
- OAuth 配置指导覆盖 Google Cloud、同意屏幕、客户端信息、环境变量和授权步骤；凭据由操作系统受保护存储管理，永不回显或写入配置。
- 覆盖矩阵使用 `已支持`、`部分支持`、`资格限制`、`估算或会调整`、`异步处理中` 和 `不可用` 状态。每项事实查询均可关联其适用状态与数据截至时间。
- 本机数据仓库和官方 API 适配层通过稳定的事实合同隔离，为未来服务器部署保留迁移边界，但本期不实现远程服务。

## Testing Decisions

- 最高测试接缝是 CLI 的 JSON 合同。测试从真实 CLI 命令入口运行，并使用本地伪造的 OAuth 与 YouTube 官方接口边界，不访问真实账号或浏览器。
- 测试频道选择、首次回填、分页与检查点恢复、配置临时覆盖、分析配置档案、配额状态、异步状态、过期回退和强制最新失败等外部可见行为。
- 为配置校验、指标/维度兼容目录、覆盖状态映射、数据新鲜度计算和原始证据保留策略保留聚焦单元测试；断言业务合同而非内部实现细节。
- 针对凭据保护添加回归测试，确保令牌和客户端秘密不会出现在配置文件、日志、JSON 或原始证据中。
- 使用现有 CLI JSON 测试模式和临时目录隔离本机数据仓库。所有自动测试必须可离线重复执行。
- 在自动化测试之外，提供一条人工 OAuth 验收路径，只验证授权、频道选择和最小读取范围；测试过程不提交任何凭据或真实频道数据。

## Out of Scope

- YouTube Studio 网页 UI 的逐项镜像、绕过官方接口限制或使用网页抓取获取私有数据。
- 上传、发布、编辑、删除、修改隐私、回复评论或任何其他频道写入操作。
- 直播数据、MCP 服务、内置 AI 模型、AI 因果归因和自动运营建议。
- 频道写入相关的 YouTube Reporting 变更操作、评论创建/修改/回复和其他写操作。
- 服务器部署、多用户共享、远程凭据托管和跨机器同步。
- 预下载所有指标、维度与时间范围的组合。
- 未经明确用户动作的 OAuth、源站刷新、原始证据清理或其他外部副作用。

## Further Notes

### 首期覆盖矩阵

| 数据类别                         | 首期策略                     | 覆盖状态规则                     |
| -------------------------------- | ---------------------------- | -------------------------------- |
| 频道、视频与上传播放列表元数据   | 首条链路同步                 | 已支持或资格限制                 |
| 频道与视频级表现、互动数据       | 首条链路同步                 | 已支持、部分支持或不可用         |
| 流量、设备、地域、受众、收入细分 | 按配置档案或临时参数按需获取 | 部分支持、资格限制或估算或会调整 |
| 原始证据与同步检查点             | 随每个同步范围保存           | 已支持                           |
| Reporting 异步报告               | 首条链路后扩展               | 异步处理中                       |
| 评论与其他扩展读取数据           | 首条链路后扩展               | 异步处理中或部分支持             |
| 直播数据                         | 不实现                       | 不可用（本期范围）               |

官方能力研究是本规格的数据边界证据。实际运行时必须以当前 OAuth 权限、频道资格、配额与官方 API 返回状态为准；任何未能由官方资料证实的 Studio UI 能力不得被标记为已支持。
