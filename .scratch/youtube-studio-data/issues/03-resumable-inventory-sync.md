# 03 — 可恢复的基础数据仓库同步

Type: task

What to build: 让一个已建立频道接入的运营者将频道、视频和上传播放列表元数据同步到本机运营数据仓库，并能观察和恢复中断的同步。

Blocked by: 02 — OAuth 授权与显式频道接入.

Status: resolved

- [x] 用户可以为已选择频道开始或按配置安排基础数据同步，并在本机查询到规范化的频道、视频和上传播放列表数据。
- [x] 每个同步范围保存原始证据、来源、获取时间和可恢复检查点，但不保存凭据。
- [x] 分页、网络中断或进程中止后，用户可从检查点续传，不会把已确认数据误报为未完成或重复数据。
- [x] CLI/JSON 可显示同步进度、最后成功时间、失败原因和数据截至时间。
- [x] 用户可通过本次 CLI 参数选择基础元数据同步范围，并在状态和检查点中记录实际范围。
- [x] 规范化数据默认不自动删除；原始证据清理仅针对明确频道路径。
- [x] 本机仓库仅通过窄的官方 API 适配层获取数据，CLI 事实合同不依赖具体 API 客户端实现。

## Answer

- 新增 `InventoryProvider`、分页检查点、规范化 `data.json`、原始证据目录和 `sync-state.json`。
- 新增 `ops channel sync` 与 `ops channel sync-status`，网络中断后可恢复且按资源 ID 去重。
- 验证：`test/inventory.test.ts` 3 项离线伪 API 测试通过，覆盖分页、断点和令牌脱敏；全量测试持续通过。
