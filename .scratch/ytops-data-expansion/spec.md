# 运营数据扩展：观看口径、观众画像、留存曲线、收入与曝光

Label: ready-for-agent

> 本规格由 grill-with-docs 会话综合而成，前置研究见 Further Notes。领域词汇遵循根 CONTEXT.md（观看口径、观众画像数据、留存曲线、高维细分数据、同步范围等），硬决策见 ADR 0002、ADR 0003。

## Problem Statement

频道运营者通过现有 CLI 已能同步核心表现指标（观看数、观看时长、平均观看时长、点赞、评论、分享）与按需高维细分数据，但存在五类缺口：

1. 2026-08-24 起官方将观看计数统一为"开播即计"（播放口径）且历史不重述，单一观看口径无法回答"改版前后表现是否变化"这一最基本的对比问题。
2. 订阅者/非订阅者观看结构、赞踩结构、订阅增长、观众画像、留存曲线等关键运营事实要么完全缺失，要么只能临时逐维手动查询，不在运营数据仓库中持续沉淀。
3. 总收入与千次收入（RPM）缺位：收入指标类型虽已登记，但货币权限从未接入，查询实际会失败。
4. 每期影片的曝光数与曝光点击率（缩略图与标题吸引力）没有任何获取通道。
5. Reporting 数据落盘为每频道单槽位，任何新增报表都会覆盖既有报表。

## Solution

在保持只读运营操作与最小权限边界（ADR 0001、ADR 0003）的前提下，扩展同步范围与事实查询面：

1. **观看口径双采**（ADR 0002）：核心同步同时保存播放口径与互动口径观看数；新增不喜欢、新增订阅、流失订阅指标；派生指标（RPM、赞踩比）一律读取时计算。
2. **观众画像数据默认同步**：analytics-sync 默认包含画像阶段，频道级×日四个维度组（流量来源、国家、年龄与性别、订阅状态）；视频级画像维持按分析配置档案按需获取。
3. **留存曲线**：新增只读数据源，同步管线（首次全量断点续传 + 之后只拉新发现视频）与按需事实查询命令并存。
4. **收入 opt-in**（ADR 0003）：货币权限默认不申请、显式开启后同步总收入（显式 USD），RPM 按互动口径分母派生；未开启时收入查询本地拒绝、绝不伪装成零值。
5. **曝光与点击率**：前置完成 Reporting 多类型存储改造后，接入频道级 reach 基础报表（日期×视频粒度），获得每期影片的每日曝光数与曝光点击率。
6. **贯穿语义**：所有新数据源附数据截至时间、覆盖状态与原始证据；隐私阈值单元格省略而非置零；回填深度沿用 365 天默认、命令行可调、上限 3650 天。

### 验收标准

- 一次核心同步后，运营数据仓库同时包含两种口径的观看序列、新增/流失订阅序列、不喜欢序列，以及四个维度组的频道级画像数据。
- 留存同步首次对库存全部视频建立全历史留存曲线且可断点续传；后续每轮只处理新发现视频；按需命令返回单个视频的曲线。
- 未开启货币 opt-in 时，收入相关查询返回显式 permission 语义且覆盖状态受限；开启后收入以 USD 同步，RPM 由原始量在读取时派生。
- 曝光报表与既有 Reporting 数据并存保存、互不覆盖；同步幂等语义保持。
- 所有新事实查询返回数据截至时间、覆盖状态与原始证据引用；隐私阈值造成的空单元格被省略。
- 全量校验门禁通过，包括 skills 文档入口字符串合同与面向用户元数据简体中文合同。

## User Stories

1. 作为频道运营者，我希望核心同步同时保存播放口径与互动口径观看数，以便跨 2026-08-24 改版前后进行一致对比。
2. 作为频道运营者，我希望改版前的历史观看序列保持原口径不被改算，以便历史事实与官方公开计数保持一致。
3. 作为频道运营者，我希望核心同步包含不喜欢数，以便计算喜欢与不喜欢的比率。
4. 作为频道运营者，我希望核心同步包含新增与流失订阅，以便追踪频道的增长与流失。
5. 作为频道运营者，我希望文档说明新增订阅在视频级仅统计该视频观看页，以便正确解读视频级数据。
6. 作为频道运营者，我希望 analytics-sync 默认同步频道级的观众画像数据（流量来源、国家、年龄与性别、订阅状态），以便无需逐维手动查询。
7. 作为频道运营者，我希望画像数据按日粒度沉淀在运营数据仓库并附原始证据，以便长期追踪观众与来源结构的变化。
8. 作为频道运营者，我希望订阅者与非订阅者的观看时长可按频道与时间对比，以便了解订阅观众的消费深度。
9. 作为频道运营者，我希望每期影片的观众画像仍按分析配置档案按需获取，以免视频×维度组合拖垮配额。
10. 作为频道运营者，我希望首次留存同步对库存全部视频建立全历史留存曲线并支持断点续传，以便大库存频道也能可靠完成初始化。
11. 作为频道运营者，我希望后续留存同步只处理新发现的视频，以便每轮同步成本与新增内容线性相关而非与库存总量相关。
12. 作为频道运营者，我希望通过按需命令查询单个视频的留存曲线，以便临时分析不必等待同步。
13. 作为频道运营者，我希望留存曲线如实呈现超过 100% 的点，以便理解重复观看与叠加播放。
14. 作为频道运营者，我希望在显式开启货币权限后同步总收入（美元），以便收入数据进入统一仓库。
15. 作为频道运营者，我希望货币权限默认不申请、由显式配置开启，以便保持最小权限。
16. 作为频道运营者，我希望未开启货币权限时收入查询被明确拒绝而非显示零值，以便缺失数据不被误读为真实事实。
17. 作为频道运营者，我希望收入以显式 USD 币种获取，以便收入口径没有歧义。
18. 作为频道运营者，我希望 RPM 在读取时按互动口径派生，以便与官方"收入锚定互动观看"的口径一致。
19. 作为频道运营者，我希望诊断命令显示货币权限的 opt-in 状态与资格提示，以便授权前了解频道要求。
20. 作为频道运营者，我希望每期影片的每日曝光数与曝光点击率进入仓库，以便评估缩略图与标题对展示转化的影响。
21. 作为频道运营者，我希望多种 Reporting 报表数据并存保存，以便新增曝光报表不覆盖既有报表数据。
22. 作为频道运营者，我希望曝光报表的同步节奏考虑官方报表保留窗口，以便长期数据不断档。
23. 作为运维 agent，我希望所有新事实查询返回数据截至时间、覆盖状态与证据引用，以便输出可核验的结论。
24. 作为运维 agent，我希望隐私阈值造成的空单元格被省略而非置零，以便不产生虚假事实。
25. 作为运维 agent，我希望中断的留存同步从检查点恢复，以便网络或配额问题不导致重复拉取。
26. 作为频道运营者，我希望覆盖矩阵新增能力条目及其资格限制，以便一眼看出哪些数据可用、受限或未授权。
27. 作为证据复查者，我希望新数据源的原始响应证据落盘且不含任何凭据，以便事后可审计。
28. 作为频道运营者，我希望新增数据沿用 365 天默认回填与命令行可调参数，以便与现有同步行为一致、不新增配置面。

## Implementation Decisions

- **观看口径与核心指标集**（ADR 0002）：核心指标集扩展为播放口径观看、互动口径观看、观看时长、平均观看时长、点赞、不喜欢、评论、分享、新增订阅、流失订阅；两种观看口径在同一请求中获取，不增加请求数；历史不重述，改版前序列保持原口径；RPM 与赞踩比为读取时派生值，RPM 分母为互动口径。
- **观众画像阶段**：同步范围默认包含频道级×日的四个维度组（流量来源、国家、年龄与性别合并为一次查询、订阅状态），每组携带核心指标集（含互动口径）；落盘结构与核心同步同构（状态、数据、证据三件套）；订阅状态同时进入按需细分的维度白名单；指标与维度白名单、配置校验、说明登记必须作为单一事实源同步扩展，避免双份清单漂移。
- **留存曲线模块**：新的只读数据源，沿用既有的依赖注入形状；同步任务 = 首次全量（按视频清单分页推进、支持断点续传，复用既有同步任务的检查点模式）+ 增量（仅新发现视频）；曲线为单视频全历史、固定比例横轴约一百个点、数值可超过 1；按需事实查询复用最后可用数据与强制最新查询语义。
- **货币权限**（ADR 0003）：独立的显式 opt-in 配置与开关，与现有分析权限追加机制分离；scope 追加仅当 opt-in 开启；未开启时收入查询在本地拒绝并映射为资格受限覆盖状态；币种参数显式 USD；诊断命令新增 opt-in 状态布尔（只报状态不报值）；实现必须包含真实频道探针步骤以裁决官方文档在频道级收入可用性上的自相矛盾，探针结论回写文档后方可承诺频道级收入行为。
- **Reporting 多类型存储**：落盘目录按报表类型划分，状态与数据互不覆盖；覆盖矩阵按报表类型分别呈现；首个接入报表为频道级 reach 基础报表（日期×频道×视频粒度，曝光数与曝光点击率指标）；既有幂等与短路语义沿用；文档必须写明官方报表保留窗口（约 60 天、历史报告约 30 天）对同步节奏的约束。
- **覆盖矩阵**：新增观众画像数据、留存曲线、曝光/CTR、收入四类能力条目；状态映射沿用现有六态枚举与 permission-denied 到资格受限的语义；证据路径过滤凭据样文本的审计断言延续。
- **命令面**：新命令挂频道运营子树，采用 sync/status/read 三件套命名惯例；面向用户文本为简体中文；README 与 skills 的入口字符串合同同步更新。
- **配置契约**：不新增全局同步配置键；货币 opt-in 是唯一新增配置面，其校验、说明登记与设置命令同步扩展；频道级覆盖模式沿用。

## Testing Decisions

- 好测试只测外部行为：同步后的落盘数据与状态、命令的 JSON 输出与退出码、错误与覆盖状态语义；不测内部函数拆分或私有数据结构。
- **库层接缝（主接缝）**：依赖注入假 provider + 内存凭据存储 + 临时目录 + 手写连接状态；先例为 analytics、breakdowns、reporting、oauth 的既有测试；新增留存模块沿用同一注入形状，不引入新接缝。
- **CLI 接缝（既有）**：spawn 构建产物 + `--json` 断言退出码与 JSON 字段；先例为 analytics-cli、cli 既有测试；新增失败分类进合同纯函数做表驱动断言。
- **合同层（既有门禁）**：skills 文档入口字符串合同与面向用户元数据简体中文合同必须随新命令通过。
- 覆盖矩阵测试沿用磁盘状态构造方式（不注 provider），断言新能力条目与证据不泄密。
- 关键行为用例：双口径并存且同请求获取；画像阶段默认执行、四维度组与指标集正确；留存首次全量断点续传与增量只拉新视频；货币未开启拒绝、开启后 USD 与派生 RPM 正确；多报表并存不覆盖；曝光报表导入幂等；隐私阈值单元格省略。

## Out of Scope

- 按观看行为细分观众群（新/回访观众）——无任何官方 API，已确认排除。
- 字幕与语言占比——仅弱口径报表可得，已确认排除。
- 会员、SuperChat、购物收入——无官方 API，已确认排除。
- 联署营销商品——无官方 API，爬取方案因违反服务条款排除。
- 带流量来源/设备细分的曝光报表（reach combined 变体）——列为后续可选，不在本期。
- analytics 的定时自动调度——本次为命令语义，调度扩展另行决策。
- 视频级观众画像默认同步——保持按分析配置档案按需获取。
- Shorts 2025-03-31 之前的互动口径回填——官方未提供，无法实现。
- content owner（CMS）多客户收入路径——本产品面向单频道主 OAuth。
- 一切写入型操作——只读运营操作边界不变。

## Further Notes

- 实现前必读研究文档：`.scratch/ytops-data-expansion/api-capability-research.md`——全部指标/维度的官方名称、约束（隐私阈值、月末调整、保留窗口、口径锚定）与一手来源引用都在其中。
- 官方文档存在两处自相矛盾（频道级收入可用性；查询式 API 缺失曝光指标而仅 Reporting API 可得），唯一裁决方式是真实频道实测，相关工票必须包含探针步骤。
- 观看口径的后续风险：官方已将多数核心分析指标锚定互动口径；若未来出现指标更名或淘汰，以官方修订历史页为准更新白名单。
- 切票顺序建议（供 to-tickets 参考）：观看口径与核心指标 → 观众画像阶段 → 留存曲线模块 → 货币 opt-in → Reporting 多类型存储与曝光报表 → 覆盖矩阵与文档合同收尾；白名单多处同步与覆盖矩阵条目是易交叉点，宜由单张工票收口。
